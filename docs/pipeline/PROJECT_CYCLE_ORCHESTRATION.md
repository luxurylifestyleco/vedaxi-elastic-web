## Loop vocabulary

Only locally documented mechanisms are used:

- **Module Gate:** claim -> bounded implementation -> deterministic assertions -> evidence -> `PASS`, `REPAIR`, or `STOP`. A failed gate feeds back to the same module.
- **Dual Delphi nodes:** isolate Node A mechanics and Node B experience, freeze both, then give them to a neutral arbiter. One evidence-backed repair pass is allowed. See [Dual Delphi](../evaluation/DELPHI_PROTOCOL.md).
- **Red-Green-Refactor (TDD):** establish the failing behavioral check, implement the smallest passing change, then refactor while keeping the focused and affected suites green. The approved scope assigns TDD to evidence search, lifecycle, actions, persistence, and state transitions in [Build Scope](../VEDAXI_BUILD_SCOPE.md).
- **Task/review/fix:** a bounded implementation is followed by independent review; actionable findings return to a repair worker for at most five repair rounds, followed by whole-branch review. A new failure after the limit becomes a blocker rather than an unbounded loop.
- **Independent Parallel Dispatch:** dispatch only when prerequisites already exist and files, mutable state, and suspected root cause are disjoint. Completion is an evidence-bearing handoff, not a verbal status.
- **Continuous Evaluation:** deterministic checks -> multidimensional scoring -> human/adversarial judgment -> regression. See the [hard-quality gate](../../evals/hard-quality/README.md).
- **Graph Feedback — deferred:** no `graphify-out/graph.json` exists in the repository, so no executable graph loop is claimed. Until that artifact exists, an upstream change follows the documented manual rule: reopen its owner, version its eval, record downstream impact, and rerun affected integration evidence.

`Diamond` is only a **decision node** in this ledger: use it to select `PASS`, `REPAIR`, `BLOCKED`, or `STOP` from completed evidence. No Double Diamond recipe is claimed or implied.

The VAOS integration ECE lane is repository-backed through stages `00`–`07`: audited source identity and audit, Kernel, Epistemic, Provenance, Skeptic, Synthesis, independent Verification, and Human Gate. Verification passed the evidence discipline of the recommendation only. The [Human Gate](../decisions/vaos-integration/07-human-gate.md) remains `AWAITING HUMAN DECISION / NO ACTION AUTHORIZED`; no VAOS runtime, persistence, adapter, experiment, or release integration is authorized.

## Stale-agent and cycle reconciliation

At each ten-minute boundary, compare the live roster, this matrix, `git status --short`, and the evidence paths above.

1. An agent is **stale** when its status is `ACTIVE` but it is absent from the live roster or has not returned the required completion packet by the boundary. Do not infer completion from elapsed time.
2. Preserve its worktree files and mark the assignment `RECONCILE`; never dispatch another writer to those files until a read-only diff identifies the exact ownership state.
3. Accept completion only with `COMPLETED`, `EVIDENCE`, `FAILURES`, `FILES OWNED`, `DEPENDENCIES`, and `NEXT 10-MINUTE BATCH`. A present file without that packet is an artifact, not an approved outcome.
4. Recount each department toward its three-assignment cycle target. Refill a free slot only with a dependency-ready, non-overlapping assignment.
5. Close the defined cycle only when every scheduled row has a recorded outcome (`COMPLETED`, `BLOCKED`, or explicitly `CARRIED`) and the release checkpoint records deterministic results, quality vetoes/floors, blockers, user-owned inputs, and the next queue. Sub 5 remains explicit carryover until redispatched or closed.
